## Dependency notes

- **01 → everything**: the pytest harness (`conftest.py` fixtures `test_db`, `client`) is created in plan 01 Task 1.

- **04 and 06 both touch `sync_abs`**: plan 04 changes its return to a tuple. Both plans carry ordering notes; running them in rank order (04 first) is the tested path.
- **05 and 06 both hook `run_full_sync`/`sync_abs`** — sequential execution avoids merge conflicts.

## Instructions for the executing session

1. Work in `/mnt/c/Tools/bookclub` on `main` (or a feature branch per plan if preferred — see superpowers:using-git-worktrees).
2. Read `CLAUDE.md` and `docs/ops-runbook.md` → "Known Gotchas" first.
3. Execute one plan at a time with **superpowers:executing-plans** (or subagent-driven-development), checking off steps.
4. Tests: `.venv/bin/pytest -q` from repo root. The venv is created in plan 01; keep its packages in lockstep with the Dockerfile pins.
5. Deployment: `app/` code hot-reloads (bind mount + `--reload`). Rebuild only for Dockerfile changes: `docker compose up -d --build`. Compose/env changes: `docker compose up -d`.
6. Commits: conventional, one purpose each, **no Co-Authored-By/AI-attribution lines** (owner preference).
7. After each plan: update `.wolf/memory.md`, log any bug fixed to `.wolf/buglog.json`, and update `docs/` per the plan's docs task.
